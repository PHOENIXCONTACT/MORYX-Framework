# How to use strategies

>[!NOTE] The [strategy pattern](https://en.wikipedia.org/wiki/Strategy_pattern) has a dedicated place in the MORYX Framework and is directly supported by its dependency injection.

This tutorial shows how a server module delegates part of its behavior to an exchangeable strategy, and how the strategy is selected in the module configuration using a [name based selector](../articles/framework/dependency-injection.md#name-based-component-selector). The same general structure can be applied to [configuration-based selectors](../articles/framework/dependency-injection.md#config-based-component-selector) as well.

>[!TIP] To use strategies in a resource, continue with [How to use strategies in resources](how-to-use-strategies-in-resources.md) afterwards.

The strategies used in this tutorial are defined in [Moryx.Samples](../../src/Moryx.Samples/Strategies/) and shared with the resource sample.
In the TestModule, the strategy is selected in the [ModuleConfig](../../src/Moryx.TestModule/ModuleController/ModuleConfig.cs), registered in the [ModuleController](../../src/Moryx.TestModule/ModuleController/ModuleController.cs) and resolved in the [TestPlugin](../../src/Moryx.TestModule/Plugin/TestPlugin.cs).

## Define the strategy interface

```cs
public interface IWhiteSpaceRemovingStrategy
{
    string DropSpaces(string s);
}
```

If strategies shall be implemented in other projects, place the interface in an assembly these projects can reference.

## Implement the strategies

For named strategies, as the name suggests, each strategy is a plugin with a unique name.
The name is what is stored in the configuration and shown in the UI.

```cs
[Plugin(LifeCycle.Singleton, typeof(IWhiteSpaceRemovingStrategy), Name = StrategyName)]
public class RegexWhiteSpaceRemovingStrategy : IWhiteSpaceRemovingStrategy
{
    public const string StrategyName = "Regex Remover";

    public string DropSpaces(string s) => Regex.Replace(s, @"\s+", "");
}

[Plugin(LifeCycle.Singleton, typeof(IWhiteSpaceRemovingStrategy), Name = StrategyName)]
public class LinqWhiteSpaceRemovingStrategy : IWhiteSpaceRemovingStrategy
{
    public const string StrategyName = "Linq Remover";

    public string DropSpaces(string s) => string.Concat(s.Where(c => !char.IsWhiteSpace(c)));
}
```

Use `LifeCycle.Singleton` for stateless strategies, all users share the same instance. Use `LifeCycle.Transient` if a strategy holds state.

## Define the factory

The configuration only holds the name of the strategy. A factory turns the name into an instance, its implementation is generated by the container:

```cs
[PluginFactory(typeof(INameBasedComponentSelector))]
public interface IWhiteSpaceRemovingStrategyFactory
{
    IWhiteSpaceRemovingStrategy Create(string name);

    void Destroy(IWhiteSpaceRemovingStrategy instance);
}
```

If you declare the interface `internal`, the assembly needs `[assembly: InternalsVisibleTo("DynamicProxyGenAssembly2")]`.

Keep the following behavior of the factory in mind:

- An unknown name throws a `ComponentNotFoundException`.
- A `null` name does **not** fail, it returns the first registered strategy.

## Register the strategies

Every module has its own container. A strategy that is not registered there can neither be selected in the UI nor created by the factory.

Strategies and factories defined in the assembly of the module are registered automatically. Everything from other assemblies is registered in `OnInitializeAsync` of the `ModuleController`. As the strategies and the factory of the sample are defined in another assembly, the TestModule registers both:

```cs
protected override Task OnInitializeAsync(CancellationToken cancellationToken)
{
    // Load externally defined named plugins
    Container.LoadComponents<IWhiteSpaceRemovingStrategy>();
    Container.Register<IWhiteSpaceRemovingStrategyFactory>();
    return Task.CompletedTask;
}
```

`LoadComponents` registers all implementations of the interface in the application, strategies that are already registered are skipped. For a strategy from another assembly to be found, the following conditions must be met:

- The strategy class is `public`. Internal classes are not found.
- The assembly is deployed to the application directory. The application does not need to reference it, copying the DLL is sufficient.
- The assembly is loaded into the application domain. Call `AppDomainBuilder.LoadAssemblies()` at the beginning of your `Program.cs`, as in [StartProject.Asp](../../src/StartProject.Asp/Program.cs). It loads all DLLs from the application directory.

## Add the selector property

The name of the selected strategy is part of the module configuration. The `PluginNameSelectorAttribute` offers the names of all strategies registered in the container of the module as possible values:

```cs
[DataMember]
[PluginNameSelector(typeof(IWhiteSpaceRemovingStrategy))]
[DefaultValue(RegexWhiteSpaceRemovingStrategy.StrategyName)]
public string WhiteSpaceRemovingStrategy { get; set; }
```

See [Possible Values](../articles/framework/Serialization/possible-values.md#pluginnameselectorattribute) for details on the attribute.

## Resolve and use the strategy

The strategy is used by a component or plugin of the module, which gets the factory and the module configuration injected as properties.

```cs
public ModuleConfig Config { get; set; }

public IWhiteSpaceRemovingStrategyFactory StrategyFactory { get; set; }

private IWhiteSpaceRemovingStrategy _strategy;

public void Start()
{
    // Config changes restart the module, so the strategy is created once per start
    _strategy = StrategyFactory.Create(Config.WhiteSpaceRemovingStrategy);
}

public void Stop()
{
    if (_strategy != null)
        StrategyFactory.Destroy(_strategy);
    _strategy = null;
}
```

## Troubleshooting

| Symptom | Cause |
|---------|-------|
| The drop-down is empty or a strategy is missing | The strategy is not registered in the container of the module. |
| A strategy from another assembly is missing | The class is `internal`, the DLL is not in the application directory, or `AppDomainBuilder.LoadAssemblies()` is not called. |
| `ComponentNotFoundException` when creating the strategy | The selected name does not match a registered strategy, e.g. after a strategy was renamed or its assembly removed. |
| The wrong strategy is created | The selected name is empty, so the first registered strategy is returned. |
| Two strategies, but only one is listed | Both use the same `Name`. Only the first registration is kept. |
