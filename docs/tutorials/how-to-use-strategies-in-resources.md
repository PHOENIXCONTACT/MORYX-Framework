# How to use strategies in resources

This tutorial shows how a [Resource](../../src/Moryx.AbstractionLayer/Resources/Resource.cs) delegates part of its behavior to an exchangeable strategy, and how the strategy is selected in the resource UI using a [name based selector](../articles/framework/dependency-injection.md#name-based-component-selector). The same general structure can be applied to [configuration-based selectors](../articles/framework/dependency-injection.md#config-based-component-selector) as well. 

>[!TIP] If you have not created a resource before, start with [How to create a resource](how-to-create-resource.md).
>[!TIP] The complete sample is in [StrategyUsingResource.cs](../../src/Moryx.Resources.Samples/StrategyUsingResource.cs). A strategy defined in another project is in [Moryx.Resources.Samples.Strategies](../../src/Moryx.Resources.Samples.Strategies/StringBuilderWhiteSpaceRemovingStrategy.cs).

## Overview

A named-strategy-based resource, consists of these parts:

| Part | Purpose |
|------|---------|
| Strategy interface | Contract all strategies implement |
| Strategy implementations | Plugins with a unique `Name` |
| Selector property | Persisted name of the selected strategy, offered as a drop-down by the `PluginNameSelectorAttribute` |
| Factory | Creates the selected strategy by its name |
| `DependencyRegistration` | Registers strategies and factory in the container of the *ResourceManagement* |
| `ISubInitializer` (optional) | Registers strategies defined in other assemblies |

All resources and their dependencies live in the container of the *ResourceManagement* module. A strategy that is not registered there can neither be selected in the UI nor created by the factory.

## Define the strategy interface

````cs
public interface IWhiteSpaceRemovingStrategy
{
    string DropSpaces(string s);
}
````

If strategies shall be implemented in other projects, place the interface in an assembly these projects can reference, e.g. the resource assembly itself or a shared contracts assembly.

## Implement the strategies

Each strategy is a plugin with a unique name. The name is what is stored in the resource and shown in the UI.

````cs
[Plugin(LifeCycle.Singleton, typeof(IWhiteSpaceRemovingStrategy), Name = "Regex Remover")]
public class RegexWhiteSpaceRemovingStrategy : IWhiteSpaceRemovingStrategy
{
    public string DropSpaces(string s) => Regex.Replace(s, @"\s+", "");
}

[Plugin(LifeCycle.Singleton, typeof(IWhiteSpaceRemovingStrategy), Name = "Linq Remover")]
public class LinqWhiteSpaceRemovingStrategy : IWhiteSpaceRemovingStrategy
{
    public string DropSpaces(string s) => string.Concat(s.Where(c => !char.IsWhiteSpace(c)));
}
````

Use `LifeCycle.Singleton` for stateless strategies, all resources share the same instance. Use `LifeCycle.Transient` if a strategy holds state per resource.

## Define the factory

The resource only knows the name of the strategy. A [name based factory](../articles/framework/dependency-injection.md#name-based-component-selector) turns the name into an instance:

````cs
[PluginFactory(typeof(INameBasedComponentSelector))]
public interface IWhiteSpaceRemovingStrategyFactory
{
    IWhiteSpaceRemovingStrategy Create(string name);

    void Destroy(IWhiteSpaceRemovingStrategy instance);
}
````

The factory implementation is generated by the container. If you declare the interface `internal`, the assembly needs `[assembly: InternalsVisibleTo("DynamicProxyGenAssembly2")]`.

## Register strategies from the same assembly

The *ResourceManagement* registers all resources with `Container.LoadComponents<IResource>()`. While doing so, it evaluates the `DependencyRegistrationAttribute` of each resource and registers all components of the **resource assembly** that export one of the listed types. List the strategy interface and the factory:

````cs
[ResourceRegistration]
[DependencyRegistration(typeof(IWhiteSpaceRemovingStrategy), typeof(IWhiteSpaceRemovingStrategyFactory))]
public class StrategyUsingResource : Resource
{
    ...
}
````

The attribute only scans the assembly of the resource. Strategies from other assemblies are ignored, see the next section.

## Register strategies from other assemblies

Strategies are often implemented in another project, for example to keep customer-specific implementations out of the resource assembly. Those strategies are registered with an `ISubInitializer`, referenced by the `DependencyRegistrationAttribute`:

````cs
public class WhiteSpaceRemovingStrategyInitializer : ISubInitializer
{
    public void Initialize(IContainer services)
    {
        services.LoadComponents<IWhiteSpaceRemovingStrategy>();
    }
}

[ResourceRegistration]
[DependencyRegistration(typeof(IWhiteSpaceRemovingStrategy), typeof(IWhiteSpaceRemovingStrategyFactory),
    Initializer = typeof(WhiteSpaceRemovingStrategyInitializer))]
public class StrategyUsingResource : Resource
{
    ...
}
````

The initializer is registered together with the resource and executed by the *ResourceManagement* after its own initialization, before any resource is loaded. `LoadComponents` registers all implementations of the interface in the application, strategies of the resource assembly that are already registered are skipped.

The strategy in the other project references the assembly containing the interface and is implemented like any other strategy:

````cs
[Plugin(LifeCycle.Singleton, typeof(IWhiteSpaceRemovingStrategy), Name = "StringBuilder Remover")]
public class StringBuilderWhiteSpaceRemovingStrategy : IWhiteSpaceRemovingStrategy
{
    ...
}
````

For `LoadComponents` to find the strategy, the following conditions must be met:

- The strategy class is `public`. Internal classes are not found.
- The assembly is deployed to the application directory. The application does not need to reference it, copying the DLL is sufficient.
- The assembly is loaded into the application domain. Call `AppDomainBuilder.LoadAssemblies()` at the beginning of your `Program.cs`, as in [StartProject.Asp](../../src/StartProject.Asp/Program.cs). It loads all DLLs from the application directory.

## Add the selector property

The name of the selected strategy is a persisted property of the resource. The `PluginNameSelectorAttribute` offers the names of all strategies registered in the container of the *ResourceManagement* as possible values:

````cs
[PluginNameSelector(typeof(IWhiteSpaceRemovingStrategy))]
[DataMember, EntrySerialize]
public string Strategy { get; set; }
````

`DataMember` persists the selection, `EntrySerialize` shows the property in the resource UI. See [Possible Values](../articles/framework/Serialization/possible-values.md#pluginnameselectorattribute) for details on the attribute.

## Resolve and use the strategy

The factory is injected into the resource as a property. The selection can be changed in the UI while the resource is running, therefore the sample resolves the strategy when it is needed and creates a new one if the name changed:

````cs
public IWhiteSpaceRemovingStrategyFactory StrategyFactory { get; set; }

[EntrySerialize]
public string DropSpaces(string text) => GetStrategy().DropSpaces(text);

private IWhiteSpaceRemovingStrategy GetStrategy()
{
    // The selection can be changed at runtime, so resolve again if necessary
    if (_strategy != null && _strategyName == Strategy)
        return _strategy;

    ReleaseStrategy();

    if (string.IsNullOrEmpty(Strategy))
        throw new InvalidOperationException($"No strategy selected for resource {Name}.");

    _strategy = StrategyFactory.Create(Strategy);
    _strategyName = Strategy;
    return _strategy;
}

private void ReleaseStrategy()
{
    if (_strategy == null)
        return;

    StrategyFactory.Destroy(_strategy);
    _strategy = null;
    _strategyName = null;
}

protected override void OnDispose()
{
    ReleaseStrategy();
    base.OnDispose();
}
````

Keep the following behavior of the factory in mind:

- An unknown name throws a `ComponentNotFoundException`.
- A `null` name does **not** fail, it returns the first registered strategy. Check for an empty selection yourself, as the sample does.
- Strategies created by the factory should be passed to `Destroy` when they are no longer used. This releases transient strategies; singletons are not affected.

## Troubleshooting

| Symptom | Cause |
|---------|-------|
| The drop-down is empty or a strategy is missing | The strategy is not registered in the *ResourceManagement* container. Check the types listed in `DependencyRegistration`, the `Initializer`, and the conditions for strategies from other assemblies. |
| A strategy from another assembly is missing | The class is `internal`, the DLL is not in the application directory, or `AppDomainBuilder.LoadAssemblies()` is not called. |
| `StrategyFactory` is `null` | The factory interface is not listed in `DependencyRegistration`, or the resource is missing the `ResourceRegistrationAttribute`. |
| `ComponentNotFoundException` when creating the strategy | The stored name does not match a registered strategy, e.g. after a strategy was renamed or its assembly removed. |
| Two strategies, but only one is listed | Both use the same `Name`. Only the first registration is kept. |
